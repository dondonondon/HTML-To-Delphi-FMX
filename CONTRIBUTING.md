# Contributing

Issues and focused pull requests are welcome. Keep each change scoped to one skill or one documented interaction between skills.

1. Edit the canonical files under `.agents/skills/`. Keep links to sibling skills and supporting files valid.
2. Preserve the `name` and `description` front matter in every `SKILL.md`. Update examples or references when a rule changes.
3. For FMX behavior claims, identify the Delphi version and target platform used. Label source review, build, designer, and runtime checks separately.
4. If you add screenshots, state the source HTML, toolchain, model/workflow, and whether a later refinement step was used. Do not overwrite historical captures to represent a new run.
5. Keep local projects, generated files, and private notes out of pull requests. `.gitignore` defines the intended public scope.

The dashboard HTML and screenshots are demonstration material. New contributions should not add credentials, proprietary project code, or third-party assets without redistribution rights.
